# Find a transaction

**What this does:** lists an account's payments and delegations in a range of blocks, with the status, amount, fee, memo, and block of each.

**When to use it:** to confirm that a payment landed and was applied, for example to credit a deposit.

## Query

Send to the [Archive Node API](/node-operators/data-and-history/archive-node-api), for example `https://devnet-archive-node-api.gcp.o1test.net`.

```graphql
query FindTransaction($address: String!, $from: Int!, $to: Int!) {
  userCommands(
    input: { address: $address, from: $from, to: $to, status: CANONICAL }
  ) {
    hash
    kind
    from
    to
    amount
    fee
    memo
    nonce
    status
    failureReason
    blockInfo {
      height
      timestamp
      chainStatus
    }
  }
}
```

## Notes

- The query finds commands by account, not by hash. A command matches when `address` is its fee payer, sender, or receiver. To find one hash, query its sender over a small range of heights and match `hash` in the result.
- `from` is inclusive and `to` is exclusive. Keep the range narrow so the query stays fast.
- `status: CANONICAL` returns only finalized blocks. Use `PENDING` or `ALL` to include recent blocks, which can still be replaced in a reorganization.
- A command in a block can still have failed. Check that `status` is `applied`, and read `failureReason` when it is `failed`.
- `amount` and `fee` are nanomina strings: this payment sent 1.34910274 MINA with a 0.25 MINA fee. The memo above is the empty memo.
- A command that is not in any block yet is in the transaction pool. See [Pending transactions](./pending-transactions).
