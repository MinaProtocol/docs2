# Network status

**What this does:** reports whether a daemon is synced, which network and chain it follows, its height, and the current epoch and slot.

**When to use it:** before you trust anything else a node returns, or as a health check in monitoring.

## Query

Send to the daemon GraphQL API, for example `https://devnet-plain-1.gcp.o1test.net/graphql`.

```graphql
query NetworkStatus {
  networkID
  syncStatus
  daemonStatus {
    blockchainLength
    highestBlockLengthReceived
    chainId
    consensusTimeNow {
      epoch
      slot
      globalSlot
      startTime
      endTime
    }
    consensusConfiguration {
      slotDuration
      slotsPerEpoch
      k
    }
    peers {
      peerId
    }
  }
}
```

## Variables

None.

## Notes

- `syncStatus` is one of `CONNECTING`, `LISTENING`, `OFFLINE`, `BOOTSTRAP`, `CATCHUP`, or `SYNCED`. Only read chain data from a `SYNCED` node.
- While a node is behind, `blockchainLength` is lower than `highestBlockLengthReceived`.
- `slotDuration` is in milliseconds, and `startTime` and `endTime` are Unix milliseconds. Read the slot length from the node rather than hard-coding it.
- Two nodes on the same network report the same `chainId`. A different `chainId` means a node is on another chain, for example one that has not followed a hard fork.
- `peers` can be long. Leave it out if you only need sync state.
